SEÇÕES (nesta ordem):
1. sec:6-9-1 "Contando passos: o que é custo computacional" — custo como número de operações elementares em função do tamanho da entrada n; contar passos de um laço simples (soma de n potenciais: ~n operações) e de laços aninhados (comparar todos os pares de neurônios: n(n−1)/2 pares; com 100 neurônios são 4950 pares, com 1000 são 499500); melhor caso × pior caso (busca linear numa lista). Definição intuitiva de O(f(n)): "cresce no máximo como f(n), a menos de constantes, para n grande" — descarte constantes e termos menores (3n² + 5n + 2 é O(n²)). Exemplo biológico: correlações entre todos os pares de neurônios de um registro.
2. sec:6-9-2 "As classes de complexidade mais comuns" — O(1), O(log n), O(n), O(n log n), O(n²), O(2^n); tabela com o número aproximado de operações para n = 10, 10³ e 10⁶ (confira cada valor; use log na base 2 e arredonde: log₂(10³) ≈ 10, log₂(10⁶) ≈ 20); busca em lista (in) é O(n) e em set/dict é O(1) em média (tabela de dispersão, explicação intuitiva); busca binária O(log n) numa lista ordenada (bisect) explicada com a analogia de procurar uma palavra no dicionário; ordenar é O(n log n). Exemplo biológico: verificar se cada um de 10000 IDs de genes está numa lista de 20000 genes de referência — lista × conjunto (estime a ordem de operações nos dois casos).
3. sec:6-9-3 "Medir tempo e vetorizar" — time.perf_counter() antes e depois; o módulo timeit e o comando mágico %timeit no Colab/Jupyter; variabilidade e por que repetir medições; estimar o expoente dobrando n (se o tempo quadruplica ao dobrar n, o custo é ~n²). Vetorização: laço Python × operação NumPy para o mesmo cálculo (z-score de 10⁶ amostras; contagem de cruzamentos de limiar com np.sum((v[:-1] < lim) & (v[1:] >= lim))); por que o NumPy é mais rápido (laços em C compilado, memória contígua, sem checagem de tipo a cada elemento). TEMPOS: nunca escreva tempos exatos; escreva "na ordem de" e "varia conforme a máquina" (ex.: a versão NumPy costuma ser dezenas de vezes mais rápida). Armadilha comum: vetorizar não muda a complexidade O(·), só a constante; e medir uma única vez.
4. sec:6-9-4 "Memória" — bits e bytes; float64 ocupa 8 bytes, float32 4, int16 2; arr.nbytes e arr.dtype; listas Python guardam objetos e gastam bem mais memória que arrays (sys.getsizeof de forma qualitativa); estimar o tamanho de dados antes de carregar: EEG de 64 canais a 1000 Hz por 1 hora em float64 = 64 · 1000 · 3600 · 8 bytes = 1 843 200 000 bytes ≈ 1,84 GB (≈ 1,72 GiB); fMRI com 64 × 64 × 40 voxels e 300 volumes em float32 = 64·64·40·300·4 = 196 608 000 bytes ≈ 197 MB; matriz de correlação de 100000 voxels em float64 = 10¹⁰ · 8 bytes = 80 GB (não cabe na RAM do Colab, que tem cerca de 12 GB — diga "cerca de"). Confira cada uma destas contas. Estratégias: dtypes menores, processar em blocos (chunks), não guardar o que não precisa. Armadilha comum: confundir MB (10⁶) e MiB (2²⁰).
